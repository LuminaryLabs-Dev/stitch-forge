# Security Policy

## Reporting a vulnerability

Do not disclose vulnerability details, credentials, personal data, or exploit code in a public issue, discussion, pull request, or commit. Request a private reporting channel from a repository maintainer before sharing sensitive technical details.

Include the affected commit and repository-relative paths, dependency versions, impact, minimal reproduction, and suggested mitigation when safe. Redact local paths, browser data, generated exports, and credentials.

## Scope

Reports may cover the browser application, pattern generation and export, Three.js rendering, Vite build configuration, GitHub Pages workflow, and declared npm dependencies.

The inspected application is static and browser-local. It does not document a backend, authentication system, external API, or persistent user-data service.

## Support status

The repository does not currently document a supported-version matrix, response target, dedicated security contact, or coordinated-disclosure schedule. Identify the affected commit in every report so maintainers can determine its status.
